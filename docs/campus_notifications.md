## 本机配置

1. 打开本地网页的「配置」页，填写年级、学院、专业、DeepSeek API Key 和模型名称。
2. 填写浙大学号、密码、学年起始年和学期。先点「测试统一身份认证（不保存）」：结果会分别显示 CAS、教务课表和学在浙大待办是否成功及条数，测试不会保存任何内容。
3. 需要计划任务自动同步时，勾选「记住密码」后保存。密码只以本机 `runtime_local/.secret_key` 派生的 Fernet 密文写入配置；不勾选则保存时清除旧密码，接口自动同步不可用，可改用专用浏览器会话；`api-check` 仍可临时输入密码做只读测试。密码框留空表示保留已保存的密码。
4. 在钉钉开发者后台创建应用机器人，启用单聊能力并选择 Stream 接收模式，完成可用范围及应用发布。在本地页填写 Client ID、Client Secret；可用 senderStaffId 限定收件账号。
5. 配置页沿用现有邮箱设置。密钥与邮箱授权码使用 `runtime_local/.secret_key` 加密；备份时同时保留配置和密钥文件，避免丢失解密能力。
6. 接口不可用或需要读取公开通知时，使用「校内事项」→「打开校内登录窗口」。在两个标签页登录；学在浙大需点击「进入平台」，教务可打开当前学期课表。返回命令窗口按 Enter 保存入口并关闭专用浏览器。浏览器会话作为接口的补充与回退。
7. 启用校内检查，点击「现在检查校内通知」。核对真实作业、公告和课表；自动发现失败时，在配置页填写课程作业/公告入口及教务课表入口。入口限定校内域名。
8. 课表包含周次或单双周时，填写本学期第一周的周一日期。缺少此日期的周次课程保留在课表视图并显示警告，暂不放入某一天的课程安排。课程日期以教务页面为准，节假日调课仍需核对。
9. 点击「启动钉钉监听」，单聊发送一条文字，收到「已记录」后核对收件箱。修改机器人凭证后，需要重启监听进程；计划任务启动的监听可用 Windows 任务计划程序停止后重启。
10. 点击「安装每日检查与登录启动任务」，或运行下面的安装命令。再次登录电脑后验证监听能自动连接。

## 命令行与计划任务

在项目目录运行；示例使用本机虚拟环境：

```powershell
.venv\Scripts\python.exe launcher.py web
.venv\Scripts\python.exe campus_monitor.py login
.venv\Scripts\python.exe campus_monitor.py sync
.venv\Scripts\python.exe campus_monitor.py doctor
.venv\Scripts\python.exe campus_monitor.py api-check
.venv\Scripts\python.exe campus_monitor.py status
.venv\Scripts\python.exe campus_monitor.py listen
.venv\Scripts\python.exe campus_monitor.py daily

# 仅验证配置，不注册任务
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/setup_campus_tasks.ps1 -DryRun
# 配置和真实来源核对完成后注册任务
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/setup_campus_tasks.ps1
```

`daily` 会执行同步、生成今日计划、发送每日计划及临期邮件。CLI 运行结果存于 `runtime_local/logs/campus_monitor.log`；来源及邮件错误也可在网页端查看。

`api-check` 执行一次只读登录与读取，输出 CAS、教务课表、学在浙大待办状态和各来源条数，不落库、不保存凭证、不打印密码或 Cookie。已有加密密码时直接复用；没有时提示输入学号和密码。两项服务都成功时退出码为 0，否则为 1。

`doctor` 有错误项时退出码为 1，只有警告时为 0；`doctor --json` 输出可供脚本读取的结构化结果。网页端「校内事项」顶部也会显示同一份自检结果。

## 同步策略与课表保护

- 有可用的加密凭证和有效学年/学期时，同步先走统一身份认证接口：CAS 登录后分别建立教务与学在浙大会话，读取本学期课表和待办，无需启动 Chrome。
- 公开通知、个人通知页面和接口未覆盖的入口仍使用专用浏览器；接口登录失败时自动回退浏览器，已有浏览器会话仍可工作。
- 空课表或课程数少于上次一半时，保留旧课表并显示警告，避免页面未加载或部分读取覆盖正常数据；只有检测到学期变更时才允许替换为更小的课表。
- 接口成功但未建立专用浏览器时，来源状态会提示「未建立专用浏览器」，不影响已同步的课表与待办，但公开/个人通知页面可能仍不完整。
- SSO 票据、服务 Cookie 和密码不会写入数据库、日志或运行记录；浏览器 Cookie 只存在于本机专用 Chrome 配置目录。

| Windows 任务 | 触发 | 运行方式 |
| --- | --- | --- |
| DailyAutomation_CampusDaily | 每天 09:00，漏执行后补运行 | 当前已登录用户，pythonw 隐藏运行，最长 1 小时 |
| DailyAutomation_DingTalkListener | 当前用户登录 | pythonw 隐藏运行，失败后重启，不限运行时长 |

09:00 使用 Windows 本地时区；本机已验证为 China Standard Time。注册脚本会关闭属于本项目的旧 `DailySchedule` 独立计划邮件任务，保留合并后的计划邮件。其他自行安装的早间流程若也发送计划邮件，应在 Windows 任务计划程序中检查重复入口。

注册成功后会写入 `runtime_local/tasks_installed.json`，供 `doctor` 判断是否安装过。该文件只是安装记录，不会实时反映任务是否被删除或禁用；需要时请在 Windows 任务计划程序中核对。`-DryRun` 不写该文件。

## 通知如何进入计划

- **收件箱**：按来源与通知编号去重；手工和单聊重复文字/链接按内容去重。同一通知正文变化时保留版本并重新摘要。
- **摘要**：优先处理个人课程和个人事务，其次是公开通知；每轮最多整理 30 条，其余保留待摘要，可点击重试继续处理；发布超过 180 天的公开通知只归档、不调用模型。每条最多向模型发送 12,000 字通知正文及必要筛选信息，移除链接、常见手机及证件号码。模型请求关闭思考模式，避免推理 token 截断 JSON；单条失败保留待重试，不阻塞整批。
- **日期**：截止依据须出现在原文。暂定、多个候选日期、时间范围和截断正文进入待核对。仅有日期时保留日期，不添加凭空推测的时刻。
- **待办**：一则通知可包含多个动作。建议开始日期参考课程负荷和已有每日任务；点击「加入个人计划」后才进入该天的任务安排。未确认日期不发送确定时间的临期提醒。
- **改期**：截止日期变化后清除旧计划日期与完成标记，等待重新确认。保留原通知链接；粘贴通知可从待办中打开本地原文。
- **提醒**：合并计划使用已有邮箱配置。相同日期的每日邮件和同一事项、截止日期、提醒阶段的临期邮件，在正常重复运行时只发送一次。发送失败释放记录以便重试；SMTP 本身不能保证断网或强制终止时的绝对单次投递，异常后应核对实际收信。

## 使用边界

- 校内公开通知每次检查最近最多 200 条；发布超过 180 天的通知只归档为历史记录，不自动分析，避免旧截止日期进入计划。文字正文未取到时保留通知编号与链接，显示待核对。
- 登录后采集读取已渲染的课程、作业、通知和课表页面。接口采集依赖教务与学在浙大的内部接口和字段；平台升级、学期代码变化或风控策略调整可能导致失败，届时回退浏览器并标记来源状态，不以读取失败表示无通知。
- 接口请求只用于本人账号的只读同步，不保存 SSO 票据或服务 Cookie，不绕过验证码、限流或访问控制。出现验证码、限流或账号异常时停止该轮接口同步并提示，不反复重试。
- 仅处理单条文字和可读取的公开 HTTPS 链接。登录链接、文件、图片、合并转发和正文过长的链接需要补充原文。原文不会因读取失败而被丢弃。
- 电脑关闭、未登录或监听不在线时，机器人消息没有已确认的历史补取通道。未收到确认回复，请在网页端粘贴补录。每日检查也依赖本机开机和用户登录。24/7 云端收件（serverless 队列或常开主机）已评估但本阶段不实现，凭证托管、离线补取和去重仍需单独设计。
- 模型可能误判断相关性、动作或工作量。原文与版本可在收件箱查看，相关性和截止日期可人工修改；AI 建议须由本人确认后排入计划。
